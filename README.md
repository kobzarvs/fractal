# Burning Ship — Rust / WASM + GPU

Локальный исследователь фрактала Burning Ship с глубоким увеличением, маршрутами и встроенной проверкой точности/скорости. CPU-часть написана на Rust и компилируется в WebAssembly, параллельный расчёт пикселей остаётся в WebGL2.

## Запуск

Нужен Node.js 24+ и браузер с WebGL2:

```sh
npm ci
npm run dev
```

Откройте http://127.0.0.1:5173/?route=western-armada&iter=16384&zoom=10

Готовые scalar/SIMD WASM-файлы включены в репозиторий. Для их воспроизводимой пересборки нужны Rust, target `wasm32-unknown-unknown` и Binaryen (`wasm-opt`):

```sh
rustup target add wasm32-unknown-unknown
npm run build:wasm
npm test
npm run test:rust
npm run build
npm run preview
```

Проверенная цепочка сборки: Rust 1.98.1, Binaryen 132, Node 24.13.0. `npm run build` проверяет TypeScript и собирает приложение с уже собранными WASM-файлами; после изменения Rust сначала выполняйте `build:wasm`.

## Управление и проверка

- Колесо масштабирует относительно курсора, перетаскивание перемещает камеру.
- «Начать полёт» ведёт к выбранной точке; ползунок сразу задаёт глубину маршрута. «Обзор» возвращает весь фрактал.
- Режим «Авто» предпочитает WASM SIMD и использует scalar при отсутствии поддержки SIMD. JS-эталон, scalar и SIMD доступны также явно; фактический вариант виден в диагностике. Число итераций и сэмплов AA задаёт пользователь. Разрешение соответствует реальному `devicePixelRatio` и автоматически не уменьшается.
- Кнопка «Проверить точность и скорость» запускает прогретые CPU/GPU-сравнения и позволяет скачать JSON. GPU-время берётся из аппаратных timer queries, если расширение поддерживается.
- `npm run bench` выдаёт JSON CPU-бенчмарка в Node/V8. Это отдельное измерение, а не оценка FPS браузера.

## Реализация

`crates/fractal-core` вычисляет опорную орбиту целыми массивами разрядов, затем строит BLA-матрицы и Float32-текстуры. Signed shifts, дополнительная точность, fold/celtic и округления проверяются относительно независимого JS BigInt-эталона. В горячем цикле нет выделений памяти. Параметры ядра: 1–4096 бит, 1–65536 итераций; координаты ABI передаются десятичными строками целых чисел в масштабе `2^bits`.

Вычислительный worker переиспользует WASM instance. `Memory.toResizableBuffer()` включается по наличию API; старые браузеры используют обновляемые views фиксированного буфера. Задачи разбиты на порции с бюджетом около 4 мс и уступают event loop через MessageChannel. Результаты копируются в пул transferable-буферов; WASM memory не выдаётся за transferable или «zero-copy GPU».

GPU сохраняет direct / float perturbation / extended-range perturbation, BLA, rebase и палитру. Шейдер вычисляет уровень BLA целочисленными масками и повторно использует чтение Celtic-текстуры; исходный вариант доступен для сравнения. Константная специализация fold/celtic была отклонена после расхождения пикселей. Temporal AA накапливает центрированные сэмплы, перепроецирует историю при движении и сбрасывает её при смене параметров. Кольцевой кэш включён для полёта: исходная плотность выборки, полноразмерный fallback при нехватке места.

Для ручной проверки восстановления главного canvas добавьте `&diagnostics=1` к URL и нажмите «Проверить восстановление GPU». Автоматический benchmark отдельно проверяет этот lifecycle, совпадение кадров после восстановления и отмену настоящих Worker-задач.

Rust выбран для управляемой линейной памяти, нативных тестов и предсказуемого ABI. WebAssembly здесь — цель компиляции, а не конкурирующий язык. Сравнительного теста Rust против MoonBit не проводилось.
