## Цель и исходные условия

Сделать браузерный Burning Ship с глубоким зумом, перенеся подходящие CPU-циклы в WASM и проверив оптимизации GPU-шейдеров. Сохранить точность, детализацию, палитру и сглаживание при одинаковых параметрах. Ускорение принимать только по замерам.

Пользователь выбрал гибрид WASM + GPU и поручил выбрать язык реализации. Выбор — Rust с компиляцией в `wasm32-unknown-unknown`. WebAssembly является форматом исполнения. MoonBit поддерживает Wasm, WasmGC и BigInt, но для этого проекта Rust удобнее явным управлением массивами разрядов, линейной памятью, SIMD и нативными тестами. ## Разделение ответственности

| Компонент | Реализация | Ответственность |
| --- | --- | --- |
| Интерфейс, ввод, URL | TypeScript | Камера, параметры, запуск тура, настройки качества |
| Опорная орбита | Rust/WASM в Web Worker | Знаковая арифметика фиксированной точки с необходимым числом разрядов |
| BLA | Тот же Rust/WASM | Матрицы блоков и границы допустимости, упаковка результатов |
| Рендер | WebGL2, GLSL ES 3.00 | Direct, float perturbation, extended-range perturbation |
| Кэш и сглаживание | GPU | Логарифмические кольца, temporal AA, финальный composite |
| Проверка и замеры | Отдельный режим приложения и тесты | Эталон JS, сравнение данных и кадров, CPU/GPU timings |

Сначала сохраняется WebGL2, чтобы сравнивать одинаковые вычисления и не смешивать перенос CPU-части с заменой графического API. WebGPU остаётся возможным следующим экспериментом после подтверждённого профиля GPU-ограничений.

## WASM-ядро и точность

1. Координаты и орбита представлены целыми массивами разрядов. Сохраняется исходная точность камеры плюс 32 рабочих бита, поведение отрицательного арифметического сдвига, квантование fold/celtic и критерий остановки.
2. Исходная орбита последовательна: следующий шаг зависит от предыдущего. SIMD применяется только к независимым операциям, для которых подтверждено совпадение результата.
3. Вычисления BLA сохраняют порядок операций и правила преобразования в Float32. Математические функции библиотек могут округляться иначе, чем JS Math; это отдельный предмет дифференциальных тестов, а не предположение об идентичности.
4. Большая задача выполняется порциями через явный `begin/step/result` ABI. Отмена проверяется между порциями; устаревший результат не публикуется.
5. ABI передаёт указатели, длины и скалярные параметры. В горячем цикле нет вызовов JavaScript, сериализации JSON, создания строк и временных массивов.
6. Выпускается единственная simd128-сборка, для которой подтверждены эквивалентность и выигрыш. Второй движок — исходный JS BigInt. Отдельного scalar-варианта и автоматического выбора нет.
7. Сборка release использует оптимизацию LLVM, LTO и проверенный проход Binaryen. Fast-math и relaxed SIMD не используются для изменения численных результатов.

## Память и актуальные возможности Chrome

Базовая схема — один долгоживущий WASM instance в вычислительном worker и повторно используемые scratch/output-буферы. Ёмкость выделяется перед задачей по числу итераций и разрядности. В ходе итераций память не растёт и объекты не выделяются.

При наличии `WebAssembly.Memory.prototype.toResizableBuffer` выбирается resizable-представление памяти один раз. Для глобального доступа используются length-tracking views; границы опубликованных массивов задаются явными offset/length. Режим буфера не переключается в горячем пути. В совместимом fallback после `memory.grow` представления создаются заново. Рост памяти выполняется только в подготовке задачи и проверяется отдельно от вычислений.

`toResizableBuffer` и `toFixedLengthBuffer` отмечены в MDN browser-compat-data как доступные с Chrome 144. Перед использованием это дополнительно проверяется в целевом браузере. Сам API не считается доказательством ускорения.

WASM-owned ArrayBuffer нельзя передавать как обычный transferable. В базовой схеме готовый компактный результат копируется в отдельные переиспользуемые ArrayBuffer, передаётся renderer с transfer ownership и после загрузки в GPU возвращается в пул. Упаковка Float32 уже выполнена WASM; дополнительных JS-массивов для неё нет. Передача данных в GPU остаётся отдельной операцией и измеряется.

После базовых замеров отдельно сравниваются два способа убрать межпоточное копирование:

- WASM и WebGL2 в одном worker с OffscreenCanvas: загрузка текстур из views WASM-памяти, вычисления орбиты порциями с ограниченным временем, чтобы не задерживать кадры.
- Общая WASM-память для вычислительного и рендерящего потоков: только при поддержке всей цепочки API, cross-origin isolation и явном протоколе владения двумя слотами результата. Совместимость shared views с используемыми GPU API проверяется; отсутствие CPU-копии не предполагается автоматически.

В основную сборку попадает вариант с лучшими p95 задержками и памятью без регрессии ввода/рендера. Memory64 не нужен при объёмах ниже 4 GiB: он расширяет адресное пространство, а не численную точность. WasmGC не является требованием для Rust-ядра с повторно используемыми буферами.

## Оптимизации шейдеров

В исходном движке уже существуют BLA, compile-time SHIP_PATH, texelFetch для орбиты, переключение FE/native float, пакетный рендер и кольцевой кэш. Они сохраняются как база сравнения.

Первые отдельные эксперименты:

1. Специализированные варианты для `fold=1, celtic=0`, убирающие uniform-ветвления. Арифметические выражения и порядок округлений сохраняются. Для остальных параметров остаётся общий вариант.
2. Целочисленное определение уровня выравнивания BLA вместо float log2. Используется дерево проверок масок до 10 уровней, совместимое с GLSL ES 3.00; findLSB не предполагается доступным в WebGL2.
3. Вынесение одинаковых atan/log2 при смешивании соседних кольцевых полос в одно вычисление на пиксель. Если драйвер уже устраняет повторение, изменение не объявляется ускорением.
4. Переиспользование уже прочитанного `realOrbit` в Celtic-ветке вместо повторного texelFetch на том же шаге.

Изменение размера итерационных пакетов и переход кольцевого кэша на аппаратную билинейную фильтрацию — отдельные эксперименты с риском иных округлений. Они не включаются в режим сохранения качества без проверки и объяснения отличий.

## Качество и критерии принятия

Проверяются общий план, граница перехода direct/perturbation, float/FE, глубокие точки Western armada, пересечения осей, rebase, допустимость BLA, fold/celtic и швы кольцевых полос.

- Для целочисленной орбиты требуется точное совпадение с JS BigInt-эталоном, включая отрицательные сдвиги и округление при экспорте.
- Для опубликованных Float32 orbit/BLA массивов сравниваются байты и отдельно происхождение каждого отличия. Оптимизация не принимается автоматически по одному похожему изображению.
- GPU baseline и оптимизированный вариант сравниваются в одном браузере на одном GPU, при одинаковых координатах, разрешении, числе итераций, AA и фиксированной последовательности jitter. Различия в escape classification — ошибка. Отличия сглаженного счётчика и цвета анализируются отдельно; необъяснённые различия блокируют включение оптимизации.
- Точность между разными GPU не обещается побитовой. Это отдельное ограничение существующего GLSL-рендера.
- Снижение разрешения, бюджета итераций или сглаживания не засчитывается как ускорение. В режиме сравнения адаптивное качество зафиксировано.
- Проверяются повторные задачи, отмена, рост памяти, возврат буферов, resize и восстановление после потери WebGL-контекста.

## Производительность и результаты

Отдельно измеряются подготовка орбиты, построение BLA, упаковка/копирование, GPU upload, рендер фрактала и сборка кольцевого кадра. GPU-время получается через доступное `EXT_disjoint_timer_query_webgl2`; недоступные или disjoint измерения не подменяются CPU-временем.

В отчёте фиксируются Chrome/ОС/GPU, параметры сцены, scalar/SIMD, особенности памяти, холодный старт и прогретые p50/p95. Частота requestAnimationFrame сама по себе не используется как доказательство скорости рендера: неподвижные кадры могут браться из кэша.

Результат реализации: запускаемое локальное приложение, воспроизводимая сборка WASM, численные тесты, режим сравнения и отчёт с фактическими выигрышами и отклонёнными экспериментами. Целевой процент ускорения заранее не назначается.
